# גנרטור עמודי SEO — מניינים

מייצר עמודי HTML סטטיים מנתוני Supabase, כדי שגוגל יאנדקס את זמני
התפילה של השכונה. כל עמוד מסתיים בקריאה להורדת האפליקציה.

## הרצה

```bash
cd generator
npm install

node build.js --dry --out ../     # מדפיס מה ייווצר, לא כותב כלום
node build.js --out ../           # יוצר את הקבצים
```

המפתח נקרא אוטומטית מ-`app/.env` שכבר קיים ברפו. אין מה להגדיר.

## מה נוצר

```
minyanim-har-homa/
├── index.html                עמוד אינדקס — כל בתי הכנסת
├── slugs.json                מיפוי id → slug. אל תמחק.
└── <שם-בית-כנסת>/index.html  עמוד לכל בית כנסת
sitemap.xml
robots.txt
```

## `slugs.json` — אל תמחק

ברגע ש-slug הוקצה לבית כנסת הוא נשמר כאן ולא משתנה, גם אם השם משתנה
במסד. מחיקת הקובץ תייצר כתובות חדשות ותשבור כל קישור שגוגל כבר אינדקס.

הקובץ חייב להיות בקומיט.

## סנכרון עם האפליקציה

`lib/prayers.js` הוא שכפול ב-JS של `prayer_sort_service.dart` ושל
`prayer_utils.dart`, ו-`lib/season.js` משכפל את `_isPrayerInSeason`.

**כל שינוי במיפוי `set` בדארט חייב להשתקף כאן**, אחרת האתר והאפליקציה
יציגו סדר שונה לאותם נתונים.

נקודות שקל לפספס:
- `הנץ החמה` ממופה ל-`sunrise − minutes` (שעת ההתחלה, לא שעת הסיום)
- סליחות ממוינות אחרונות (עדיפות 4)
- סינון עונתי חובה — בלעדיו סליחות יופיעו בדצמבר

## הבדלים מכוונים מול האפליקציה

| | האפליקציה | הגנרטור |
|---|---|---|
| זמני היום | מחושבים ליום הנוכחי | תאריך ייחוס אחד (אמצע אפריל) |
| `צמוד` | חוצה בתי כנסת | בתוך אותו בית כנסת בלבד |
| צאת הכוכבים | לפי מעלות (kosher_dart) | קירוב, שקיעה + 20 |

העמוד סטטי ונבנה פעם ביום; הסדר היחסי בין מניינים כמעט לא משתנה
לאורך השנה. הקירובים משפיעים על **מיון בלבד** — התצוגה תמיד מילולית
ולקוחה ישירות מהמסד.

## הרחבה לשכונה נוספת

```bash
COMMUNITY_ID=<uuid> node build.js --out ../
```

צריך גם לשנות את `SECTION` ב-`build.js` ואת שמות המקום בתבניות.
